01 / FOUNDATIONS

컬러 Color

브랜드의 중심은 Primary Blue. 바탕과 글자는 차분하게, 장식은 필요한 곳에만 사용합니다.

SEMANTIC ROLES

같은 흰색, 다른 역할

--surface는 콘텐츠 면, --cta는 흰 알약 버튼의 바탕입니다. 헤더 문의 버튼의 글자는 파랑, 드로어 문의 버튼의 글자는 검정입니다.

LOCAL ACCENTS

장식색은 페이지의 맥락 안에서

#FF3EA5#22D3EE#8CFF3F

홈의 마젠타·시안·라임은 home.css의 지역 변수입니다. 공통 의미색이나 성공·경고·오류색으로 확대하지 않습니다.

CONTRAST / 계산값

글자와 바탕은 함께 선택합니다.

출처: common/css/tokens.css, presentation.css, home/css/home.css. --line은 장식선·카드 테두리용입니다. 입력·선택 UI처럼 경계가 기능을 구분할 때는 --line-ui: color-mix(in srgb, var(--ink) 55%, var(--surface))를 사용합니다. 상태색 체계는 현재 공통 토큰으로 정의되어 있지 않습니다.

페이지 이동과 펼침을 구분

  • 오른쪽 드로어: 화면 80%, 최대 360px.
  • 메뉴명은 이동, 오른쪽 화살표만 하위 목록 펼침.
  • 한 번에 한 그룹만 펼침. 현재 카테고리 표시.
  • 딤·Escape로 닫기, 초점 복귀·키보드 경로 유지.
  • 닫기 버튼은 키보드 초점이 오면 표시.
ACCESSIBILITY & MOTION

모양을 넘어 동작까지

  • 아이콘 버튼 44×44px, 모바일 메뉴 항목 44px 이상.
  • 현재 메뉴 aria-current, 펼침 aria-expanded.
  • 장식은 aria-hidden, 주요 이미지는 대체 텍스트.
  • prefers-reduced-motion: reduce 대응 유지.
  • 색만으로 선택 상태를 구분하지 않기.

현재 소스에는 1100·1180px 등 보조 분기점도 있습니다. 위 표는 공통 구조의 주요 기준이며 모든 페이지를 하나의 분기점으로 합치기 위한 규칙이 아닙니다. 접근성 항목은 유지·검증 지침이며 사이트 전체의 적합성 인증을 의미하지 않습니다.

개발·검증 체크리스트
  1. 작업 브랜치에서 원본을 수정하고 기존 선택자·ID를 유지합니다.
  2. 공통 → 페이지 기본 → 공통/페이지 presentation → 기존 후속 CSS → 페이지 모바일 → navigation-mobile 순서를 보존합니다.
  3. npm run build, npm test, npm run check를 실행합니다.
  4. npm run preview 후 360·390·430px와 데스크톱에서 화면·동작을 확인합니다.
  5. Spring 내보내기·공개 DB 화면 영향과 미검증 범위를 기록합니다. 임시저장과 공개 발행 정책은 바꾸지 않습니다.
  6. PR로 검토하며 main 병합·배포는 소유자 승인 후 진행합니다.

이 가이드의 자체 레이아웃·색상 카드·서체 도구는 문서 UI입니다. 새 프로덕션 컴포넌트나 사이트 전반의 신규 규격으로 간주하지 않습니다. 이전 --blue*는 호환 별칭이며 새 코드에는 --primary*를 사용합니다.
